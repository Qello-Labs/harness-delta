# Isolated ordinary Codex binding qualification

[English](codex-ordinary-binding-qualification.md)

이 체크아웃은 프로덕션 허용과 별개로, 일반 대화형 Codex CLI 후보를 위한 제한된 적격성 검증 실행기를 제공합니다. 준비 단계에서는 네이티브 제품이나 모델을 실행하지 않습니다. 실행에는 고정된 의도에 대한 명시적 동의와 대화형 터미널이 필요합니다. 공개 명령에는 합성 모드 스위치가 없습니다.

과거 후보는 macOS arm64의 Codex 0.160.0이며, 바이너리 SHA256은
`112fae7a5a1223e673c8a1791d32338f37df8b527ff1159bb8adac6c4dbf1b4b`입니다.
별도의 0.162.1 후보는 macOS arm64 바이너리 SHA256
`74c6a6d263f40d65f99c27a815275f5b4ed0bcc2baecc396b4cf3255498bdfc0`에 고정됩니다.
`--product-version 0.162.1`로 명시적으로 선택하십시오. 이 옵션을 생략하면
0.160.0이 유지됩니다. 대상 버전은 의도, 프로토콜, 워크플로, 메타데이터 기록기 및 리스에 고정됩니다. 0.162.1 일반 TUI는 `--no-daemon`을 사용하므로 소유권이 확보된 시험 실행이 공유 백그라운드 서버에 연결되지 않습니다. 어느 후보도 아래에 설명한 별도 검증된 0.162.1 제한 프로필을 넘어 일반 허용을 개방하지 않습니다.

`--route ordinary_admission` 옵션은 검증된 정확한
`codex-binding-01621-direct-family-v1` 기능 파일럿 프로필과 코드가 소유하는 일반 공급자를 선택합니다. 도메인이나 바인딩 서비스에는 적격성 검증 리스를 전달하지 않습니다. 실행기는 한도, 불변 의도, 작업 범위 및 비상 종료에 대한 별도의 소유 실행 안전 가드를 유지합니다. 이 가드는 소스 접근 권한을 부여하지 않습니다. 기본값인 `--route qualification`은 과거 경로를 유지합니다.
일반 옵션을 사용할 때는 정확히 등록된 버전을 선택하십시오. 기본값은 변경되지 않습니다.

Codex 0.163.0은 별도의 정확한 제한형 일반 프로필이며, macOS arm64 바이너리 SHA256
`8813367285524ac798dd96d1b071aea30d58708c7226fd236cd275cf1cfdee31`에 고정됩니다.
같은 릴리스의 동반 실행 파일 `codex-code-mode-host`도 필요하며, SHA256은
`79f123a85dbc61e8f5d0f0c050dfc3f4b81a8305d33a32b41e008b7f6e035698`입니다.
공식 플랫폼 패키지에는 둘 다 포함되지만, 독립형 Codex 아카이브에는 포함되지 않습니다.
준비 단계는 의도를 생성하기 전에 호스트가 누락되었거나, 실행 불가능하거나, 심볼릭 링크이거나, 다른 사용자가 쓸 수 있거나, 검토되지 않은 경우 이를 거부합니다. 호스트의 정규 경로와 해시는 의도에 고정되며 실행 전에 다시 확인됩니다. `--no-daemon`은 이 소유 실행 호스트 요구 사항을 없애지 않습니다.
`--product-version 0.163.0 --route qualification`을 선택하십시오. 이 경로는 아래에 설명한 검토된 단계별 연결 절차, 단일 명령 네트워크 승인, 알림 처리 및 900초 / 관측 요청 10개 / 관측 토큰 200,000개 범위를 사용합니다. 실패했던 외부 `sandbox-exec` 시작 환경은 사용하지 않습니다.
네이티브 CLI의 읽기 전용 샌드박스와 요청 시 승인은 계속 적용됩니다.
이 버전의 적격성 검증 경로 네이티브 시험은 2026-10-16에 신규 영수증/패밀리 사용량 대조와 소유 프로세스 종료 검증을 통과했습니다. 정확히 연결된 소스 3개, 관측 요청 6개였으며, 연결 기준선 요청 3개는 제외되었습니다. 이후 별도의
`--product-version 0.163.0 --route ordinary_admission` 시험도 수집 적격성 검증 권한 없이 통과했습니다. [아래의 정확한 수락 기록](#2026-10-16-ordinary-route-acceptance)을 참조하십시오.
이 정확한 바인딩 프로필에서 향후 관측되는 데이터만 검증된 출처 정보를 받습니다.
이전 후보의 관측 데이터, 파일/워크플로 호환성, 기존 버전, 기본값 및 과거 증거는 변경되지 않습니다. 준비, 합성 회귀 테스트 및 앞선 일시적 시작 스모크 테스트는 어느 네이티브 시험도 대체하지 못합니다.

[2026-10-13 일반 경로 수락 기록](#2026-10-13-ordinary-route-acceptance)은 독립 검토를 거쳐 고정된 네이티브 바이너리에서 그 정확한 경로를 입증합니다.
이전의 리스 제한 증거와 Node 픽스처는 이 실행을 대체하거나 다른 일반 프로필을 검증할 수 없습니다.
합성 결과는 `ordinary_path_verified`를 설정할 수 있지만,
`ordinary_admission_verified`는 실제 실행만 설정할 수 있습니다. 준비 단계에서는 항상 후자를 false로 보고합니다.
이러한 모든 관측의 비용은 여전히 부분적입니다. 패밀리 대조가 성공하더라도 시도된 모든 요청, 최종 결과의 영속적 전달 또는 전체 작업 비용이 입증되는 것은 아닙니다.

0.162.1 argv는 새 정규 일회용 프로젝트만 신뢰 대상으로 표시하는 세션 전용 `projects` 인라인 테이블도 제공합니다. 사용자 설정에 폴더 신뢰를 저장하거나 읽기 전용 샌드박스/요청 시 승인 정책을 변경하지 않습니다.
실행 단계에서는 예약 전에 해당 프로젝트 안의 모든 `.codex` 항목을 거부합니다. 이를 신뢰하면 의도에 고정되지 않은 프로젝트 설정을 불러올 수 있기 때문입니다.
이 정확한 플래그는 구현과 함께 고정됩니다. 이를 변경한 후에는 이전에 소비된 의도를 재사용할 수 없습니다.
새 0.162.1 계획은 해당 세션에 한해서만 `exec_permission_approvals`도 활성화합니다. 이 기능은
[고정된 소스](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/features/src/lib.rs#L1284-L1307)에서 기본적으로 꺼져 있으며 `UnderDevelopment` 상태입니다.
고정된 `helper_network_permission`은 `single_command_network_only`입니다.
고정된 `connect-once.mjs` 프로그램은 검사한 뒤 검사가 성공한 경우에만 연결하며, 하나의 명령에서
`sandbox_permissions: "with_additional_permissions"`와
`additional_permissions: {"network":{"enabled":true}}`를 요청합니다. `file_system`은 생략하십시오.
[네트워크 오버레이는 기존 파일시스템 정책을 유지합니다](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/sandboxing/src/policy_transforms.rs#L582-L643).
재사용 가능한 접두사, 턴 또는 세션 권한 없이 해당 실행만 승인하십시오.
이는 호스트/포트 제한이 아니라 명령 전체에 적용되는 네트워크 권한입니다. 프록시 강제가 없으면 macOS는 해당 실행에 대해 인바운드 및 아웃바운드 네트워크를 허용합니다.
검토된 헬퍼 자체는 고정된 루프백 UI만 대상으로 하며 리디렉션을 거부합니다.
관리형 프록시/로컬 바인딩 제한은 여전히 이를 차단할 수 있습니다. 파일시스템 샌드박스를 제거하는 `require_escalated`로 대체하거나 프록시 정책을 변경하지 마십시오.
2026-10-13에 수락된 시험에서는 고정된 대상 바이너리에서 정확한 네트워크 전용 명령 승인과 성공적인 루프백 연결이 관측되었습니다.
과거 0.160.0 계획은 이 기능을 활성화하지 않으며 권한을 `none`으로 기록합니다.
준비 단계는 설치된 패키지와 함께 커넥터 경로 및 SHA를 고정합니다.
유일한 런타임 인수는 현재 네이티브 불투명 UUID를 사용하는 `--receipt`입니다.
네이티브 승인 화면에서는 고정된 Node 실행 파일이 정확히 해당 커넥터와 영수증을 실행하는 경우만 승인하고, 추가 플래그나 연쇄 명령은 허용하지 마십시오.
허용 횟수와 종류를 통제하는 유일한 주체는 사람 승인자입니다.
두 번째 네트워크 요청, 파일시스템 권한, 샌드박스 없는 권한 상승 또는 재사용 가능한 권한은 거부하고, 연결이 차단된 후에도 작업/자식이 계속되면 소유 프로세스를 중지하십시오. 프롬프트와 소스 측 요청 원장은 세션이 연결되기 전에는 이러한 규칙을 강제할 수 없습니다.
이 적격성 검증은 루트와 두 자식을 `gpt-6.1-sol` / `high`로 고정합니다. 이식 가능한 스킬의 모델 정책을 변경하거나 기여자에게 해당 버전 설치를 요구하지 않습니다.
다른 바이너리/런타임에는 별도의 적격성 검증이 필요합니다. Claude 일반 세션 바인딩은 별도의 후보이며, 이 명령은 이를 검증하지 않습니다.

## 0.166.0 unqualified ordinary candidate

Codex 0.166.0은 별도의 정확한 프로필
`codex-binding-01660-direct-family-v1` 아래에 있는 **미검증 후보**, `qualified:false`입니다.
검증된 지원은 대기 중입니다. 기록 자체에는 `evidenceId`나 `evidenceIntentSha256`가 없으며
`productionSourceEvidence`에 아무것도 기여하지 않습니다. 별도의 네이티브 의도와 제한된 결과는
[2026-11-03 후보 시험](#2026-11-03-candidate-trials)에 기록되어 있으며 후보의 지원 검증을 완료하지는 않습니다.
일반 설정은 이 일반 후보를 노출합니다.
그러한 노출은 적격성 검증이나 네이티브 실행 승인이 아닙니다.
새 프로젝트 설정의 기본값은 여전히 0.163.0입니다. 저장된 버전, 고정된 설정, 과거 적격성 검증 및 과거 관측 데이터는 변경되지 않습니다.
적격성 검증 명령에서 버전을 생략했을 때의 기본값은 여전히 0.160.0입니다.

정확한 macOS arm64 이미지 고정값은 다음과 같습니다.

| 이미지 | 바이트 | SHA-256 |
| --- | ---: | --- |
| CLI `codex` | 268972064 | `39acf979729dd290f9a24ee38b2914e036c91b65952872e28ae2a6b88a7db7c1` |
| 동일 디렉터리의 `codex-code-mode-host` | 69182864 | `fd37051bfdce0b65cf22a7077e265720a7bd6709d5e400dcbc26197f3041400a` |

동일 릴리스의 호스트가 필요하며, 0.163.0 호스트와는 독립적으로 고정됩니다.
호스트가 없거나 잘못된 경우 준비/실행을 거부합니다. 이러한 이미지 고정값은 대상 런타임, 훅, 권한 또는 카운터의 적합성을 입증하지 않습니다.

이 후보를 준비하려면 `--product-version 0.166.0`,
`--route ordinary_admission` 및 아래 표의 명시적 `--scenario`가 필요합니다.
0.166.0에는 적격성 검증 경로, 파일/워크플로 대체 경로 또는 네이티브 재개가 없습니다.
macOS arm64에서 Node 24와 새 일회용 등록 프로젝트/작업을 사용하십시오.
시험은 루트와 모든 자식을 `gpt-6.1-sol` / `high`로 고정합니다. 일반 GPT 계열/관측 노력 수준 정책은 변경하지 않습니다.

| 필수 시나리오 | 고정된 토폴로지와 정상 완료 |
| --- | --- |
| `root_normal_observer_restart` | 새 CLI 루트 1개, 자식 0개, 정확한 소스 1개. 연결, 활성 수집, 관측기 일시 중지/재연결, 기준선 이후의 새 루트 컨텍스트, 정상 종료 및 최종 대조 |
| `family_normal_observer_restart` | 새 CLI 루트 1개와 정확히 2개의 새 직접 ThreadSpawn 자식, 깊이 1, 정확한 소스 3개. 각 세션 자체의 사용량 수집, 관측기 일시 중지/재연결, 새 루트 컨텍스트, 정상 종료 및 최종 대조. 추가 자식 작업 없이 측정된 자식 사용량 유지 |

예를 들어 다음은 루트 시나리오만 준비하며, Codex를 시작하지 않습니다.

```sh
node scripts/codex-session-binding-qualification-command.mjs prepare \
  --directory /private/tmp/harness-delta-binding-01660-root-unique \
  --product-version 0.166.0 \
  --route ordinary_admission \
  --scenario root_normal_observer_restart \
  --binary /absolute/path/to/reviewed/codex \
  --codex-home /absolute/path/to/existing/codex-home
```

패밀리 시나리오에는 자체의 새 디렉터리와
`--scenario family_normal_observer_restart`가 포함된 정확한 의도가 필요합니다.
재시작은 새 기준선을 사용하여 동일한 활성 소스, 작업, 할당, 가격/기간 고정값 및 누적 안전 원장에 관측기를 다시 연결하는 것을 의미하며, 네이티브 재개나 재실행을 뜻하지 않습니다.
연결 전, 일시 중지 중 또는 오프라인 사용량을 소급 채우거나 이전 요청을 재생하지 마십시오.
선택된 각 세션에는 측정된 자체 사용량이 있어야 합니다. 최종 대조는 고정된 두 자식 가정이 아니라, 고정된 단일 소스 또는 세 소스 시나리오를 따릅니다.
재시작 증거 턴은 컨텍스트만 있는 행을 포함해 해당 턴을 명시하는 모든 루트 소스 행에 재시작 경계보다 엄격히 이후인 유효한 타임스탬프가 있을 때만 인정됩니다.
최종 대조는 소유 프로세스가 이미 종료되었더라도 루트 요청, 전체 요청 또는 입력+출력 토큰이 중지 기준 이상이면 거부하며, 각 자식은 계속 요청 한 개까지만 허용됩니다.

| 의도별 예산 | 고정된 한도 |

해당 루프백 UI를 열어 자동 패밀리/부분 사용량 업데이트를 확인하십시오.

## Bounds and ownership

### Manual first input in a human terminal

준비 단계는 명시적 수동 시작을 고정하기 위해 `--start-mode manual`을 허용합니다.
이 모드는 과거 0.160.0에서만 사용할 수 있습니다. 권한이 활성화된 새 0.162.1 계획은 작업 공간을 만들기 전에 수동 모드를 거부합니다. 자동 모드만 제한된 커넥터와 권한 지침을 고정하기 때문입니다.
이 옵션을 생략하면 `automatic`이 유지됩니다. 선택한 `start_mode`는 의도 다이제스트와 출력되는 준비 메타데이터에 포함됩니다. 이전 동의로 실행할 때 이를 바꿀 수 없습니다. 이 필드가 없는 이전 의도는 automatic으로 해석되지만, 기존 구현 드리프트 검사는 계속 적용됩니다.

수동 모드는 위치 인수로 전달되는 시작 프롬프트만 제거합니다. 동일한 일반 TUI, 모델/노력 수준, 임시 훅, 소스 허용, 소유 PTY, 리스, 신원 검사, 기한 및 종료 검증이 적용됩니다. `codex exec`를 실행하거나, 독립적으로 시작된 프로세스에 연결하거나, 프로덕션 바인딩을 활성화하지 않습니다.
실행기는 초기 모델 프롬프트를 제출하지 않습니다. 이 설명이 네이티브 시작 활동의 계정 사용량이 0임을 입증하지는 않습니다.

새로운 정확한 의도에 대한 실행 승인과 제한적인 폴더 신뢰 승인 후, 사람은 Node24와 `TERM=xterm-256color`를 사용하여 자신의 대화형 터미널에서 기존
`execute --intent ... --consent ...` 명령을 시작합니다. 상속된 stdin과 stdout은 키 입력과 화면 출력을 소유 PTY로 전달합니다. 사람은 정확히 준비된 작업/출처와 훅이 제공한 영수증으로 `$harness-connect`를 입력합니다. UI 운영자는 Chrome만 사용합니다. 승인된 절차를 벗어난 추가 모델 요청을 입력하거나, 두 번 재연결하거나, 추가 자식을 시작하지 마십시오. 준비 모드 선택만으로 모델 실행이나 신뢰/설정 변경이 승인되지는 않습니다.

실행 전에 명령, 첫 입력, 브라우저 및 승인을 준비하십시오.
버전별 기한은 TUI 시작과 사람의 입력 전에 예약 시점부터 시작됩니다
(0.162.1은 900초, 과거 0.160.0은 120초).
측정 일시 중지는 해당 기한을 멈추거나 실제 사용량 한도를 변경하지 않습니다.
검토된 0.162.1 중지 범위는 root8/child1each/total10이며, 과거 0.160.0 범위는 root4/child1each/total6을 유지합니다. 둘 다 제외된 설정 및 재개 기준선을 포함합니다. 의도된 새 작업은 연결에 최대 루트 요청 3개, 별도 작업 턴에 3개, 각 자식에 요청 1개를 사용하며, 추가 중지 여유분을 사용하라는 요청이 아닙니다. 사람의 메시지 하나가 반드시 네이티브 모델 요청 하나인 것은 아닙니다. 연결 확인 후 별도 자식 작업 턴을 수행하는 흐름은 완료 전에 이러한 중지 기준을 소진할 수 있습니다. 임의의 사람 조작 흐름에 충분한 예산인지는 검증되지 않았습니다. 알리지 않고 한도를 늘리지 마십시오.
완전한 사람 조작 흐름 검증에 시간이나 요청이 더 필요하면 정확한 상호작용과 버전별 한도를 별도로 검토하십시오.

입력은 사람이 통제하지만, 소유 프로세스는 안전/오류/기한 조건에 따라 계속 중지합니다.
0.162.1 프로토콜의 첫 연결 기준 수집 기간은 900초이며, 과거 0.160.0 기간은 180초를 유지합니다.
독립적인 네이티브 기한은 여전히 실행 시작부터 900초(과거에는 120초)이며, 연결, 입력 또는 재개 시 재설정되지 않습니다. 수집 자체의 기간이 더 늦게 끝나더라도 이 기한을 넘겨 수집할 수 없습니다.
Chrome의 측정 일시 중지는 에이전트를 종료하지 않고 수집을 중지합니다. 비상 중지는 소유된 적격성 검증 권한을 철회합니다. 종료 확인 실패는 계속 실패한 시험으로 남습니다. 종료가 확실히 검증된 뒤에는 `results-ui`가 네이티브 소스 읽기 없이 사람의 결과 입력/새로 고침을 지원합니다.

자동 0.162.1 모드에서 일반 TUI는 준비된 작업과 `$harness-connect`를 명시하는 고정된 연결 전용 프롬프트를 받습니다. 연결이 성공하고 해당 턴이 완료된 뒤, 운영자는 의도에 고정된 `post_connect_input`을 별도의 TUI 턴으로 한 번 제출합니다.
연결 컨텍스트에 이를 덧붙이지 마십시오. 해당 컨텍스트의 응답은 계속 제외 기준선으로 남습니다.
제출 키 없이 붙여넣고(지원되는 경우 bracketed paste 사용), 초안을 확인한 뒤 별도 동작으로 Enter를 누르십시오. 대상의 붙여넣기 버스트 감지기는 빠른 텍스트+Enter 스트림을 제출이 아니라 줄바꿈이 포함된 붙여넣기 텍스트로 처리할 수 있습니다. 전송된 턴과 활성 작업을 관측하십시오. 입력창의 텍스트만으로는 요청이 시작되었다는 증거가 되지 않습니다. 두 번째 작업 프롬프트를 보내지 마십시오.
작업 턴은 새 자식 두 개의 병렬 실행과 한 번의 대기를 요청합니다. 연결된 세 세션 각각에서 자체 사용량이 측정되고 작업 턴이 끝난 뒤, 정상 종료 경로로 유휴 TUI를 종료하십시오. 모델 프롬프트의 "stop"은 프로세스를 종료하지 않습니다. 종료 명령과 제출 키를 따로 입력한 뒤 실제 종료를 확인하십시오. 과거 자동 0.160.0 프롬프트는 단일 턴으로 유지됩니다.
Codex는 세션 설정 후 자동 시작 입력을 제출하므로 긴 입력을 입력창에 수동으로 붙여넣을 필요가 없습니다. 준비 단계는 검토를 위해 정확한 argv를 출력하고 구현 바이트를 고정합니다. 이는 여전히 일반 TUI이며 `codex exec`가 아닙니다.
네이티브 제출, 스킬 활성화 및 훅 실행은 승인된 시험에서 관측해야 합니다. 소스 호환성과 합성 argv 검사로는 이를 입증할 수 없습니다.
오프라인 지연 행 회귀 테스트는 소유 프로세스 종료를 검증한 뒤 최종 투영 직전에 신뢰된 픽스처 콜백을 사용합니다. 이는 마지막 순간 경계를 결정적으로 만듭니다. 공개 CLI에는 픽스처 스위치나 콜백이 없습니다.

프로세스 내부의 불투명 리스는 새로 예약된 저장소/작업/프로젝트, 할당, 가격 고정값, 새 루트/자식 신원 및 기한에 연결됩니다. 브라우저/프로필 필드로 이를 제공할 수 없습니다. 네이티브 이벤트는 원래 네이티브 제품을 유지하며, 실행기 증거는 `real_operations`, 통제된 Node 픽스처는 `synthetic`으로 표시됩니다.
기본 일반 프로덕션 바인딩은 계속 제한되며, 기존에 허용된 워크플로 프로필은 변경되지 않습니다.

이 스모크 테스트는 시험 한도로 루트 1개, 직접 자식 2개 및 깊이 1을 허용합니다.
제품은 여전히 여러 검증된 후손을 대상으로 합니다. 새 0.162.1 중지 한도는 관측된 자체 요청 ID 기준 루트 8개, 각 자식 1개, 총 10개이며,
0.160.0은 루트 4개, 각 자식 1개, 총 6개를 유지합니다.
0.162.1 토큰 중지 기준은 200,000이며, 0.160.0은 입력+출력 토큰 100,000개를 유지합니다.
둘 다 제외된 연결 전/재시작 기준선과 계속되는 이전 컨텍스트를 포함한 모든 자체 요청을 계산합니다. 캐시된 입력과 추론은 다시 더하지 않습니다.
네이티브 소유 프로세스의 기한은 0.162.1에서 900초
(0.160.0에서는 120초)이며, 종료 정리 예산은 최대 5초입니다. 그 안에서 최대 2초의 TERM 유예 후 KILL을 보냅니다. 정리 대상 탐색, 신원 확인 및 소멸 확인은 원래의 동일한 예산을 공유합니다.
탐색과 TERM 권한 확인도 정리 진입 시점부터 측정되는 TERM 유예를 소비하며, 이후 별도의 유예 시계를 시작하지 않습니다.
조회는 남은 시간을 사용합니다. 시간이 소진되거나 조회가 실패하면 종료는 검증되지 않은 상태로 남습니다. 폴링 시간이 소진된 경우에도 마지막 비차단 루트 회수 작업을 실행합니다.
운영체제 스케줄링으로 실패 결과 반환이 지연될 수 있습니다. 로그/백엔드 요청이 비동기이므로 관측 한도를 초과할 수 있습니다. 구독, 청구 또는 금액에 대한 하드 상한은 없으며 백엔드 취소도 보장하지 않습니다.

Python 표준 라이브러리 PTY 소유 프로세스는 제어 파이프 EOF를 통해 관측기 종료 후에도 살아남아 자체 기한을 강제합니다. 새로 소유권이 입증된 후손의 범위 내 PID/PPID/PGID/UID/시작 메타데이터만 표본 수집하며, 명령 인수나 관련 없는 세션은 수집하지 않습니다.
각 새 후손을 입증한 정확한 부모 PID/UID/시작 신원을 유지하고, 허용 전후에 해당 부모를 다시 확인합니다. 여러 그룹은 이렇게 입증된 후손에 대해서만 지원합니다. 그룹 신호를 보내기 전에는 범위가 제한된 구성원 조회 결과가 일치해야 하며, 반환된 모든 구성원은 확립된 PID/UID/시작 신원 및 현재 그룹과 일치해야 합니다. 입증된 현재 리더가 있어야만 그룹 신호를 허용합니다. 리더가 없으면 개별적으로 검증된 구성원에만 신호를 보낼 수 있습니다.
알 수 없는 구성원, 재사용/충돌 신원, 조회 실패 및 불완전한 포괄 범위는 적격성 검증을 실패시킵니다. 계보만으로 실행 파일의 목적이나 무해한 헬퍼 역할을 추론하지 않습니다. 이는 표본 수집된 OS 증거이며, 앞으로 관측되지 않을 모든 프로세스나 백엔드 작업에 대한 원자적 보장이 아닙니다.
변경되지 않은 예산 내에서 루트 종료, 관측된 모든 그룹의 소멸 및 알려진 구성원의 소멸을 명확히 확인합니다. 부재가 확인된 신원은 다시 조회하거나 신호를 보내지 않습니다. 재사용된 PID는 외부 프로세스로 취급합니다. 입증된 구성원이 그룹만 바꿨다고 해서 반드시 실패하는 것은 아닙니다. `ownershipVerified`는 입증 결과를 나타내며, 과거의 `escapedMemberObserved` 필드는 비루트 그룹 관측을 유지합니다.
이 향후 적용 계약으로 과거 실패한 시험을 재분류하지 않습니다.
비공개 증거는 고정 기한에 따른 종료와 관측기 실패를 구분합니다.
또한 첫 관측기 중지 사유를 최종 결과와 별도로 보존하고, 첫 백그라운드 수집기 오류를 고정 허용 목록 코드 또는
`unknown_collector_error`로 보존합니다. 임의의 오류 텍스트, 스택 추적 및 소스 본문은 보관하지 않습니다. 나중에 종료가 실패해도 이러한 진단 정보는 지워지지 않습니다.
첫 모니터 중지는 `stop_witness`도 유지합니다. 여기에는 고정된 조건식과 메모리 내 루트/각 자식/전체 자체 요청 수, 제외 기준선 수 및 입력+출력 토큰 수가 포함됩니다. 동시에 도달한 모든 한도를 나열합니다. 한도 초과 레코드를 거부한 수집기는 최초로 시도된 카운터를 수락된 원장과 별도로 유지합니다. 이는 거부된 레코드를 허용하거나, 한도를 변경하거나, 권한을 재설정하거나, 일시 중지된 소스를 다시 읽는 것이 아닙니다. 누락된 증빙은 null로 남습니다.
측정 행과 이러한 안전 카운터는 계정 전체 사용량을 입증하지 않습니다.
이미 표본 수집된 소유 구성원의 PID/PPID/PGID/UID/시작 메타데이터, 확립된 부모 신원 및 상대 표본 시각을 바탕으로 최대 16개의 그룹 전환을 유지하며, 명시적 잘림 플래그를 포함합니다. 구성원 조회는 관측된 해당 그룹으로 제한되며, 명령 인수나 세션 콘텐츠는 추가하지 않습니다. 기록된 그룹 전환은 무해한 헬퍼를 식별하거나 소유권 검사를 우회하지 않습니다.
소유권/종료 검사가 실패하면 성공한 실행으로 간주할 수 없습니다. 알려지지 않은 이탈이나 공급자 측 작업은 이 프로세스 입증의 범위 밖입니다. UI 일시 중지/수신기 닫기만으로는 네이티브 작업이 끝났다는 증거가 되지 않습니다.

일반 측정 일시 중지는 소유 CLI와 원래의 실제 경과 시간 감시기를 유지합니다. 활성 관측 구간을 닫고 소스 본문 읽기를 금지합니다. 별도의 비상 중지 동작은 소유 네이티브 프로세스를 종료합니다.
재개는 동일하게 살아 있는 소유 루트의 저장된 영수증만 다시 검증하고, 작업, 할당/가격 고정값 및 누적 안전 원장을 보존하며, 알려진 모든 구성원에 대해 기준선을 설정합니다.
반복 주기는 고정된 네이티브 시계나 요청/토큰 한도를 재설정하지 않습니다.
기준선 이전부터 계속된 컨텍스트는 측정에서 제외되며, 다음으로 허용된 활성 읽기에서 별도의 안전 메타데이터로 유지됩니다. 결함은 여전히 소유 프로세스를 중지시키며, 예상된 일시 중지 공백은 부분적인 상태로 남습니다.

일시 중지 중에는 소스에서 파생된 안전 카운터를 모니터링할 수 없습니다. 재개 기준선 또는 최종 활성 소스 대조는 제외 요청을 안전 한도에 포함합니다.
일시 중지 중 CLI가 종료되면 최종 본문 읽기는 허용되지 않습니다. 증거는
`safety_usage_verification: unverified`와 `task_paused_no_source_read`를 보고합니다. 하드 카운터/청구 보장은 주장하지 않습니다. 스모크 테스트는 일시 중지 중 추가 작업을 요청하지 않고 일시 중지/재개할 수 있습니다. 이는 UI 전환을 입증할 뿐, 실제 일시 중지 사용량 제외를 입증하지 않습니다.

수집기는 고정된 루트 범위 안에서 훅이 제공한 정확한 새 소스만 읽습니다.
즉, 루트 파일 1개와 자식 파일 2개이며, 네 번째 헤더/본문을 읽기 전에 메타데이터 상한을 검사합니다(충돌하는 영수증 갱신 포함). 첫 헤더는 최대 64 KiB, 각 소스는 최대 8 MiB입니다. 이전 전사를 스캔하거나 네이티브 상태 데이터베이스를 조회하지 않습니다. 소유 프로세스 종료 후에는 별도의 공급자 투영이 정확히 그 세 소스에 대해 신원/계보, 최종 공백, 모든 자체 요청의 모델/노력 수준/카운터, 요청/토큰 한도 및 저장된 관측 데이터나 명시적으로 제외된 기준선 ID와의 일치를 확인합니다. 뒤늦게 나타난 미일치 사용량은 실패 처리됩니다.
Coordinator가 추가한 소스 호환성은 최종 소스 읽기 전에 코드가 소유하는 결정 및 모든 불변 세션 고정값과 일치해야 합니다. 대조는 저장된 출처 정보를 무시하거나 JSON 속성 순서에 의존하지 않고, 네이티브 판독값을 예상 출처 정보와 비교합니다.
연결 전 기준선 사용량은 측정 사용량에서 계속 제외됩니다. 프롬프트, 응답, 소스 코드 또는 원시 행은 측정/보고 진단 정보에 들어가지 않습니다.

`evidence.json`은 고정된 실패 사유, 단계, 소스/카운터 대조, 패밀리 수 및 검증된 프로세스 결과를 기록합니다. 이 파일은 불변이며 비공개입니다. 사람의 완료 처리는 별개로 유지됩니다. 종료가 확실히 검증된 후에는 소스 없는 기록과 사람의 결과 동작만 다시 여십시오.

```sh
node scripts/codex-session-binding-qualification-command.mjs results-ui \
  --intent /private/tmp/harness-delta-binding-qualification-unique/execution-intent.json
```

세션별 행과 합계 행은 적격한 자체 요청, 입력/출력 및 고정된 부분 추정 비용을 보여 줍니다. 누락, 관측된 0 및 가격 미지정 값은 서로 구분된 상태로 유지됩니다. 이 결과 서버는 네이티브 소스를 읽거나, 실행하거나, 재연결할 수 없습니다. 새로 고침해도 기록된 결과는 유지됩니다. 수락된 일반 경로는 이 정확한 CLI 루트/직접 자식 획득 사례만 입증합니다. 다른 일반 경로, 더 넓은 토폴로지,
Claude, IDE/MCP/시스템 에이전트, 전체 비용 또는 추론에 기반한 채택 결정을 허용하지 않습니다.

## Local verification

측정 일시 중지는 구간 진단 정보를 기록하기 전에 바인딩 수집을 중지합니다.
시계 역행으로 유효한 공백이나 수명 주기 전환을 만들 수 없으면, 바인딩은 알 수 없는 구간과 함께 중지된 상태로 유지되고, 작업은 오류를 보고하며, 작업 화면에는 이전 수명 주기 상태가 계속 표시될 수 있습니다. 타임스탬프를 보정하지 않으며 어떤 구간도 소급 채우지 않습니다. 재연결 전에 시계 오류를 해결한 뒤 일시 중지를 재시도하십시오. 진행 중인 읽기나 자식 발견은 수집을 복원할 수 없습니다.
일반 측정 일시 중지는 소유 에이전트를 계속 실행 상태로 유지합니다. 적격성 검증 소유 프로세스의 별도 기한 및 비상/결함 제어는 계속 적용됩니다.

리스 세대와 패밀리 고정값은 해당 바인딩 트랜잭션이 커밋된 후에만 채택됩니다.
바인딩 쓰기가 실패하면 이러한 고정값을 진전시킬 수 없습니다. 적격성 검증 증거는 첫 고정 진단 단계/코드를 전체 종료 실패와 별도로 유지합니다. 임의의 오류 메시지와 스택은 제외됩니다.

측정 제품에는 적격성 검증 요청 한도가 없습니다. 새 0.162.1 적격성 검증 소유 프로세스는 관측값 root8 또는 total10에서 중지하며, 0.160.0은 root4/total6을 유지합니다.
0.162.1 토큰 중지 기준은 입력/출력 토큰 200000개이고, 0.160.0은 제외된 설정 요청을 포함하여 100000개를 유지합니다. 이는 보수적 중지 임계값이며, 해당 횟수 안의 모든 워크플로가 완료된다는 약속이 아닙니다. 수집기는 경계 레코드를 수락할 수 있고, 다음 소유 프로세스 모니터 표본에서 실행이 중지될 수 있습니다. 고정된 2턴 계획은 버전별 중지 규칙을 제거하거나 최소 네이티브 요청 경로를 입증하지 않습니다. 다른 시험 예산/상호작용 절차에는 별도의 검토와 승인이 필요합니다. 네이티브 성공을 주장하려고 `>=`를 `>`로 바꾸지 마십시오.

독립적으로 시작된 사람의 터미널은 적격성 검증 경로의 리스를 발급할 수 없습니다.
해당 경로는 격리된 소유 프로세스와 고정된 일회용 의도로 계속 제한됩니다.
수락된 일반 프로필은 대신 별도의 코드 소유 권한을 사용합니다.
적격성 검증 소유 프로세스를 통한 사람의 터미널 조작은 고정된 초기 프롬프트, 중지 임계값 및 검증된 정리를 유지합니다. 이는 일반적인 사용자 관리 터미널 허용이나 프로덕션 게이트를 우회하는 수단이 아닙니다.
